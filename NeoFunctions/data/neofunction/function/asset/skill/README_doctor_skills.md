## 剣士から引き継いだルール

- ダメージ・効果量は `scores={LVL=0..29}` 等のブラケットで自動スケーリング（スキル個別Lvは無し）
- SP消費は固定値。`scoreboard players remove @s SP <値>`
- コンボ演出はタグ＋`schedule`による自動解除（猶予時間の管理）
- 奥義は「発動（タメ）→schedule→着弾処理」の2段構成

## トリガーON/OFF方式（今回維持した独自要素）

- `tag @s add skillXXXtrigger` の有無で分岐
- ONの場合、追加SPを払って上乗せ効果を発動
- OFFの場合は基本効果のみ（剣士の205のような常駐トグルとは別物、単発強化トグル）

## ドクター独自のコンボ軸：weakenedタグ

- 242（劇薬強襲）が起点。命中した敵に3秒間 `weakened` タグを付与
- 243（爆裂フラスコ）・244（散布性毒霧）が猶予時間内にその敵へ命中すると追撃ボーナス
- 剣士の `exposed`（208起点）/ `airjuggled`（204起点）と同じ発想の「起点→追撃」コンボ

## 修正履歴（読み込みエラー対応）

ゲーム内ログで報告されたエラーを解消しました。

1. **`execute if/unless items entity ...`が構文エラーになる問題**
   - このサーバーのMinecraftバージョンでは`items`サブコマンドが使えない（または書式が異なる）ため、**ポーション所持数をスコアボードで管理する方式に変更**しました
   - 新設スコアボード：`DrPotionAtk`（攻撃ポーション所持数）／`DrPotionHeal`（回復）／`DrPotionBuff`（強化）
   - 241（魂の調合）で生成時に該当スコアを+1
   - 242〜249の各消費スキルは `execute unless score @s DrPotionXxx matches N.. run return ...` で所持チェックし、`scoreboard players remove @s DrPotionXxx N` で消費
   - 実際のインベントリからアイテムを取り除く処理は `neofunction:player/job/doctor/consume-attack-item` 等の別関数に切り出す形にしました（中身は未実装、要相談）。スコアボードの数値とインベントリの見た目を同期させる役目です
2. **`[scores={LVL=0..29}]`の後に二重スペースが入り構文エラーになる問題**
   - Brigadier（Minecraftのコマンドパーサー）は引数間のスペースが2つ以上あるとパースエラーになります
   - 表を揃えるために入れていた余分なスペースを全ファイルで単一スペースに統一しました
